# Exercise 1 — Prompt Engineering & Model Parameters

## Key Concepts

| Concept                        | Remember                                                      |
| ------------------------------ | ------------------------------------------------------------- |
| **PromptTemplate ⭐**           | Reusable prompt with variables like `{review}` or `{person}`. |
| **Zero-shot Prompting**        | Give only instructions; no examples.                          |
| **Few-shot Prompting**         | Give a few examples before asking the task.                   |
| **Chain-of-Thought Prompting** | Ask the model to reason step-by-step.                         |
| **Temperature ⭐**              | Controls randomness and creativity of responses.              |

## Temperature Guide

| Temperature   | Best For                                          |
| ------------- | ------------------------------------------------- |
| **0.0 – 0.3** | Factual answers, summarization, QA, instructions. |
| **0.4 – 0.6** | Balanced responses.                               |
| **0.7 – 1.0** | Creative writing, brainstorming, storytelling.    |

### Keywords

* Low temperature → **Consistent & deterministic**
* High temperature → **Creative & varied**
* Same prompt + different models = Different response styles.

# Exercise 3 — Document Loaders & Text Splitters

## Document Loaders

| Loader            | Purpose                                        |
| ----------------- | ---------------------------------------------- |
| **PyPDFLoader ⭐** | Loads PDFs into LangChain `Document` objects.  |
| **WebBaseLoader** | Loads webpage content into `Document` objects. |

## Document Object

```python
Document(
    page_content="...",
    metadata={
        "page": 0,
        "source": "LangChain_Paper.pdf"
    }
)
```

**Document = `page_content` + `metadata`**

## Text Splitters

| Splitter                             | Purpose                                            |
| ------------------------------------ | -------------------------------------------------- |
| **CharacterTextSplitter ⭐**          | Splits using characters/newlines.                  |
| **RecursiveCharacterTextSplitter ⭐** | Splits using paragraph → line → space → character. |

## Important Parameters

| Parameter           | Meaning                                    |
| ------------------- | ------------------------------------------ |
| **chunk_size ⭐**    | Maximum characters per chunk.              |
| **chunk_overlap ⭐** | Shared characters between adjacent chunks. |
| **separator**       | Preferred splitting character (e.g. `\n`). |

## Why Chunk Overlap?

Without overlap:

```text
Chunk 1 → "...helping doctors"

Chunk 2 → "detect diseases..."
```

With overlap:

```text
Chunk 1 → "...helping doctors detect"

Chunk 2 → "doctors detect diseases..."
```

Context is preserved.

###Keywords

* Chunk overlap preserves context.
* Metadata is preserved after splitting.
* Recursive splitter preserves semantic meaning better.

# Exercise 4 — Simple Retrieval System (RAG Basics)

## RAG Pipeline

```text
PDF
 │
 ▼
Document Loader
 │
 ▼
Text Splitter
 │
 ▼
Embeddings
 │
 ▼
FAISS Vector Store
 │
 ▼
Retriever
 │
 ▼
Relevant Chunks
 │
 ▼
LLM (Generation)
```

## Components

| Component        | Purpose                               |
| ---------------- | ------------------------------------- |
| **Embeddings ⭐** | Convert text into vectors.            |
| **FAISS ⭐**      | Stores vectors for similarity search. |
| **Retriever ⭐**  | Returns top-k relevant chunks.        |

## Embeddings

```text
"Artificial Intelligence improves healthcare."

↓

[0.24, -0.51, 0.89, ...]
```

Vectors represent **semantic meaning**.

## Vector Store

Stores embeddings for fast semantic search.

## Retriever

```python
retriever = vectorstore.as_retriever(search_kwargs={"k":3})
```

Returns the **top 3 similar chunks**.

## Retrieval vs RAG

| Retrieval                       | RAG                                      |
| ------------------------------- | ---------------------------------------- |
| Retrieves relevant chunks only. | Retrieves chunks + LLM generates answer. |
| Output = `Document` objects.    | Output = Natural language answer.        |

### Keywords

* Embeddings enable semantic search.
* FAISS is a vector database.
* Retriever searches vectors, not raw text.
* RAG = Retriever + LLM.

# Exercise 5 — Chatbot with Memory

## Memory Flow

```text
User Input
    │
    ▼
ConversationBufferMemory
    │
    ▼
ConversationChain
    │
    ▼
LLM Response
```

## Components

| Component                      | Purpose                                 |
| ------------------------------ | --------------------------------------- |
| **ConversationBufferMemory ⭐** | Stores the entire conversation history. |
| **ConversationChain ⭐**        | Combines LLM + Memory into a chatbot.   |

## Memory Access

| Method                          | Returns                                       |
| ------------------------------- | --------------------------------------------- |
| `memory.buffer`                 | Conversation as one string.                   |
| `memory.chat_memory.messages ⭐` | List of `HumanMessage` & `AIMessage` objects. |

## Example Memory

```text
Human: Hello, I am Megan.

AI: Hello Megan!

Human: What can you do?

AI: I can help answer questions.
```

### Keywords

* Memory preserves conversational context.
* ConversationBufferMemory stores all previous interactions.
* `verbose=True` shows the prompt + conversation history.

# Exercise 6 — SequentialChain vs LCEL

## Multi-Step Workflow

```text
Review
  │
  ▼
Sentiment Analysis
  │
  ▼
Summarization
  │
  ▼
Customer Response
```

## Traditional SequentialChain

```text
LLMChain
    │
LLMChain
    │
LLMChain
```

Each step is a separate chain.

## LCEL Workflow

```text
Prompt
   │
   ▼
LLM
   │
   ▼
Output Parser
```

Uses the **pipe operator (`|`)**.

## SequentialChain vs LCEL

| SequentialChain   | LCEL ⭐                       |             |
| ----------------- | ---------------------------- | ----------- |
| Uses `LLMChain`.  | Uses `                       | ` operator. |
| More verbose.     | Cleaner syntax.              |             |
| Fixed workflow.   | Modular & composable.        |             |
| Older API.        | Modern LangChain API.        |             |
| Harder to extend. | Easier to combine and reuse. |             |

## Output Parser

| Parser                | Purpose                              |
| --------------------- | ------------------------------------ |
| **StrOutputParser ⭐** | Converts LLM output into plain text. |

### Keywords

* SequentialChain passes outputs sequentially.
* LCEL uses the pipe operator.
* LCEL is more readable and flexible.
* Output parsers transform model outputs.

# Exercise 7 — LangChain Agents & Tools

## Agent Architecture

```text
User Question
      │
      ▼
    Agent
      │
 ┌────┴─────┐
 ▼          ▼
Calculator  Formatter
 Tool        Tool
      │
      ▼
 Final Answer
```

## Components

| Component           | Purpose                                |
| ------------------- | -------------------------------------- |
| **Agent ⭐**         | LLM that chooses tools dynamically.    |
| **Tool ⭐**          | Python function wrapped for agent use. |
| **Calculator Tool** | Performs arithmetic calculations.      |
| **Formatter Tool**  | Converts text to uppercase.            |

## ReAct Cycle

```text
Thought
   │
   ▼
Action (Choose Tool)
   │
   ▼
Observation (Tool Output)
   │
   ▼
Final Answer
```

## Chain vs Agent

| Chain                     | Agent ⭐                                |
| ------------------------- | -------------------------------------- |
| Fixed sequence of steps.  | Dynamically chooses actions.           |
| No decision-making.       | Selects tools based on user request.   |
| Same workflow every time. | Different workflow depending on input. |

### Keywords

* Agent = LLM + Tools + Reasoning.
* Tools have **name, function, description**.
* ReAct = **Thought → Action → Observation → Final Answer**.
* Agents decide which tool to use.

# AI0220 One-Line Summary (Interview Ready)

* **Prompt Engineering:** Design reusable prompts with variables and control creativity using temperature.
* **Output Parsing:** Convert LLM responses into structured formats like JSON.
* **Document Processing:** Load PDFs/web pages into `Document` objects and split them into chunks while preserving context.
* **RAG Basics:** Generate embeddings, store them in FAISS, retrieve relevant chunks, and use them as context for answers.
* **Memory:** Maintain conversational context using `ConversationBufferMemory`.
* **LCEL:** Build modular AI workflows using the `|` pipe operator.
* **Agents:** Enable LLMs to reason and use external tools such as calculators and text formatters dynamically.
